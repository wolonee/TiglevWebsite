# Фильтрация каталога — спецификация для фронтенда

Каталог — 83 402 автомобиля из базы CarClick (см. `parser/README.md`).
Этот документ описывает, какие фильтры делаем, какие не делаем и почему.

**Список фильтров не хардкодить в вёрстке.** Он генерируется из живых данных:

```bash
python3 parser/carclick.py facets      # -> parser/data/facets.json
```

Файл пересобирается после каждого обхода каталога. Марки появляются и исчезают,
счётчики плывут — вёрстка просто читает JSON и рисует по нему панель.

## Три решения, которые важно не переделать «как у всех»

### 1. Цена и пробег — диапазонами, а не ползунком

Цены идут от 160 тыс. до 151 млн, но **95% каталога лежит в 1.6–11.8 млн**.
На линейном ползунке весь каталог сожмётся в левую пятую часть шкалы, и попасть
в нужный диапазон мышью будет невозможно.

Поэтому — готовые интервалы с counts:

```
до 1.5 млн        3 397
1.5 – 2.5 млн     9 175
2.5 – 3.5 млн    11 711
3.5 – 5 млн      18 773
5 – 8 млн        25 983
8 – 12 млн       10 352
от 12 млн         4 011
```

С пробегом та же история: 95% до 110 тыс. км при максимуме 607 тыс.

Если очень хочется ползунок — он должен быть логарифмическим, и всё равно
с полями ручного ввода «от / до».

### 2. Марка — дерево с поиском, а не список

62 марки и больше тысячи моделей. Простым перечнем чекбоксов это не показать.
Нужно поле поиска по названию, популярные марки сверху, модели раскрываются
после выбора марки.

### 3. Счётчики показывать обязательно

У каждого значения в `facets.json` есть `count`. Показывать его рядом с чекбоксом —
это не украшение: пользователь сразу видит, что «Киргизия» даст 28 машин,
и не тратит клик. Пустые результаты — главная причина ухода из каталога.

## Чего сделать нельзя (и почему)

Это важно знать заранее, чтобы не закладывать в макет.

**Цвет салона.** У CarClick такой фильтр есть, у нас его не будет:
API отдаёт это поле у **0.01% лотов** (3 машины из 24 тысяч), и значения
нечитаемые — `any`, `black`. Данных просто нет.

**Комплектация.** 3326 уникальных строк вида «1.5L petrol at 150hp».
Это текст, а не категория. Показывать в карточке — да, фильтровать — нет.

**Описание.** Заполнено у 0.9% лотов. Ни фильтровать, ни показывать нечего
(и это отдельная проблема для SEO, см. `ROADMAP.md`).

**Сумма страховых выплат, история ДТП, число владельцев, VIN.**
В API не приходят вообще.

## Как фильтры работают вместе с бесконечной лентой

Это то место, где обычно ломается. Схема простая, если не использовать OFFSET.

**Запрос:**

```sql
SELECT * FROM lots
WHERE gone_at IS NULL
  AND country_code IN (:страны)
  AND brand_code IN (:марки)
  AND price_individual >= :от AND price_individual < :до
  AND id < :курсор                 -- id последней показанной карточки
ORDER BY id DESC
LIMIT 100
```

**Опции** — массив `option_ids` в строке лота, поиск через оператор
«содержит» с GIN-индексом. Одно условие на все выбранные опции, работает как «И»:

```sql
AND option_ids @> ARRAY[50, 42]     -- кожаный салон И адаптивный круиз
```

Отдельных таблиц `images` и `lot_options` **нет** — они занимали 343 МБ против
68 МБ у массивов (строка Postgres несёт 24 байта служебных данных, а полезных
в связи «лот-опция» всего 12). Галерея собирается так:

```sql
SELECT p.prefix || path FROM unnest(l.image_paths) AS path
CROSS JOIN image_prefixes p WHERE p.id = l.image_prefix_id
```

Проще — склеить префикс с массивом на стороне приложения: `image_prefix_id`
указывает на одну из четырёх строк справочника, все фото лота из одного источника.

**Правила:**

- Скролл вниз → тот же запрос с новым `курсором` (id последней карточки).
- Смена любого фильтра → `курсор` сбрасывается, лента с начала.
- **Не использовать OFFSET.** Каталог живёт: 600–700 новых машин в сутки.
  При OFFSET пользователь на середине ленты увидит дубли и пропуски.
- Если появится сортировка по цене — курсор должен стать составным `(цена, id)`,
  иначе на одинаковых ценах карточки будут теряться.

**Скорость:** фильтр по марке + цене + коробке — 3 мс, с двумя опциями — 5 мс,
счётчики для всей панели — 240 мс (их лучше пересчитывать после обхода, а не на каждый запрос).

## Состояние в URL

Фильтры должны жить в адресной строке — иначе не работает «поделиться ссылкой»,
кнопка «назад» и, что важнее, страницы фильтров не смогут попасть в поиск.

Предлагаемый вид:

```
/catalog?country=yuznaya-koreya&brand=kia&price=3500000-5000000&opt=50,42
```

Осторожно: комбинации фильтров плодят бесконечные URL. На такие страницы нужен
`canonical` на базовую категорию, иначе поисковик утонет в дублях (см. `ROADMAP.md`).

## Формат facets.json

```jsonc
{
  "totalLots": 83402,
  "detailFetched": 25030,        // счётчики опций считаются по этим лотам
  "basic":    [ /* фильтры первого уровня */ ],
  "advanced": [ /* «Все параметры» */ ],
  "optionGroups": [
    { "title": "Салон", "options": [ {"id": 50, "label": "Кожаный салон", "count": 9150, "share": 36} ] }
  ],
  "skipped":  [ /* что не построено и почему — с объяснением */ ]
}
```

Типы фильтров: `checkbox` (список значений), `range` (готовые интервалы + min/max),
`search-tree` (марка с вложенными моделями).

**Про счётчики опций:** пока идёт докачка карточек, они посчитаны не по всему
каталогу, а по загруженной части (`detailFetched`). Пропорции верные,
абсолютные числа вырастут. После завершения докачки — пересобрать файл.
