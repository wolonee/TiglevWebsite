# Выкатка в прод — что проверить

Список ведётся по факту: сюда попадает то, на чём мы уже спотыкались.
Проверять перед каждой заметной выкаткой.

---

## 1. Защита деплоев Vercel

**Оба проекта — `tiglev-website-frontend` и `tiglev-website-backend` —
должны быть открыты.** Settings → Deployment Protection → Vercel Authentication →
`Require Log In` выключен.

На чём споткнулись: бэкенд оставался закрытым, отдавал `302` на редирект входа,
а фронт молча возвращал захардкоженный массив машин вместо данных из базы.
Сайт при этом выглядел рабочим, просто показывал старое.

Нюанс тарифа: на Hobby в выпадающем списке только `Standard Protection`
и `All Deployments`. Первый защищает всё, **кроме production Custom Domains** —
то есть после привязки своего домена защиту можно включить обратно,
и превью-сборки закроются, а прод останется открытым. Пока домена нет,
работает только полное выключение.

## 2. Переменные окружения

Задавать в Production-окружении **фронтового** проекта:

| переменная | зачем |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://tiglev.com` — из неё собираются canonical, карта сайта и Open Graph. На превью-деплоях задавать свою, иначе превью канонизируется на прод |
| — | `DATABASE_URL` фронту **больше не нужен**: каталог идёт через бэкенд |
| `BACKEND_URL` | адрес бэкенда; через него идёт весь каталог |
| `BACKEND_API_KEY` | тот же ключ, что у бэкенда |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY` | вход в админку |
| `BLOB_READ_WRITE_TOKEN` | загрузка фото своих машин |

У **бэкенда** — `DATABASE_URL`, `BACKEND_API_KEY`, `TELEGRAM_BOT_TOKEN`,
`TELEGRAM_WEBHOOK_SECRET`, `FRONTEND_ORIGIN`.

Сборка фронта падает молча и без внятного текста, если переменной нет.
Проверять до выкатки: `npm run build` локально с теми же значениями.

## 3. Секреты GitHub (синхронизация каталога)

Settings → Secrets and variables → Actions:

| секрет | зачем |
|---|---|
| `DATABASE_URL` | куда писать каталог |
| `PROXY_URL` | диапазон портов прокси; **CarClick блокирует адреса GitHub и Vercel**, без прокси синхронизация не работает |
| `PROXY_EXPIRES` | дата окончания пакета, `ГГГГ-ММ-ДД`; за 10 дней придёт напоминание в Telegram |
| `TELEGRAM_BOT_TOKEN` | уведомления о сбоях |

Расписание запускается **только с ветки по умолчанию**. Файл в другой ветке лежит,
но не срабатывает.

## 4. Домен

`www.tiglev.com` до сих пор отдаётся Apache — это старый хостинг.
Пока DNS не переведён на Vercel, новый сайт виден только по адресу `*.vercel.app`.

После перевода проверить, что `NEXT_PUBLIC_SITE_URL` совпадает с тем,
какой домен сделан основным (`tiglev.com` или `www.tiglev.com`) — иначе
canonical будет указывать на другой хост, чем сам сайт.

## 5. Что учитывать, но не блокирует

**Регион.** Функции выполняются в Вашингтоне (`iad1`), база Neon во Франкфурте.
Каждый запрос платит около 100 мс через Атлантику при том, что сам запрос
выполняется за 1.7 мс. Настройка `regions: ["fra1"]` в `vercel.json`
на Hobby молча игнорируется — закрепление региона доступно с платного тарифа.

**Лимит Neon.** Free даёт 512 МБ на проект, каталог занимает около 120 МБ.
В той же базе живут заявки с сайта: при переполнении Neon переводит её
в read-only, и приём заявок ломается. Раз в месяц запускается `prune`,
уведомление приходит на 400 МБ.

**Пакет прокси месячный.** Кончится — синхронизация встанет, сайт продолжит
показывать вчерашние цены. Напоминание приходит за 10 дней.

**Партнёрка CarClick не подтверждена.** Пока не выяснено, какой параметр
(`?r=`, `?referral-code=`, `?clckid=`) засчитывается, трафик уходит к ним
бесплатно. Технически запуску не мешает, но на этом держится вся окупаемость.

## Быстрая проверка после выкатки

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://<фронт>/            # 200
curl -s -o /dev/null -w "%{http_code}\n" https://<бэкенд>/health     # 200
curl -s https://<фронт>/sitemap.xml | head -5                        # адреса, не 404
curl -s https://<фронт>/robots.txt                                   # правила
```

Если каталог пуст, а сайт жив — почти всегда виноват бэкенд: недоступен
или без `DATABASE_URL`.
